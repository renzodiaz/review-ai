AI Ruby Pull Request Reviewer

Un agente que combina RAG, RuboCop y un LLM con salida estructurada para revisar Pull Requests de Ruby on Rails en segundos.

Grupo: 5 Integrantes: [Renzo Diaz, Oswaldo Escudero] Rama: Ingeniería de Software Fecha: 11 ago 2026
01 El problema y su línea base Aplicabilidad

Revisar Ruby a mano no escala

Cada PR exige cruzar el código contra guías de seguridad, performance y convenciones del equipo, y correr RuboCop a mano. El trabajo repetitivo donde los mismos riesgos (N+1, SQL injection, mass assignment) reaparecen una y otra vez.

15–20 min
revisión manual / PR — solo para 1 solo PR
02 Qué hace el agente Funcionalidad

Le pasas un PR, te devuelve un veredicto

URL de un Pull Request de GitHub → score 0–100, hallazgos con severidad, evidencia y recomendación, y lo que sí está bien hecho todo en un reporte, no en texto libre.

03 Arquitectura y decisiones Arquitectura
03 Decisiones tecnológicas Arquitectura

Framework

OpenAI SDK (Responses API), sin LangGraph/CrewAI: una llamada estructurada por review.

Salida

Pydantic tipado: el review es evaluable y deduplicable, no texto libre.

Infraestructura

Híbrida: embeddings locales (gratis) + LLM en la nube (razonamiento).

RAG

FAISS en memoria sobre 8 guías interna suficiente a esta escala.

Herramientas

RuboCop por subprocess directo, una sola herramienta fija.

Interfaz

Gradio, construida al final sobre un núcleo ya validado en notebook.

05 Cierre + Q&A

Qué construimos

  • Un pipeline funcional: PR → RAG + RuboCop → LLM estructurado → reporte, con UI en Gradio.
  • Un benchmark propio de 10 casos con métricas reales, no solo demo anecdótica.
  • Límites conocidos: solo Ruby/Rails, repos públicos, sin memoria conversacional, próximos pasos claros.
