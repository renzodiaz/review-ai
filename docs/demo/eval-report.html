Este reporte mide dos cosas distintas: si el agente funciona (test set de 10 casos, precisión/recall/ confiabilidad) y si aporta valor (el indicador de la propuesta, antes → después). El test set dice que funciona; el indicador dice cuánto vale.

01

Metodología

evaluation/cases/ contiene 10 snippets de Ruby: 7 con un problema de ingeniería inyectado deliberadamente (uno por tipo) y 3 "limpios" que no deberían disparar ningún hallazgo — sirven para medir falsos positivos. Cada caso se corre contra el pipeline real (src/reviewer.review) y se compara el conjunto de tipos detectados contra evaluation/expected_findings.json.

Un caso con hallazgo esperado aprueba si el agente detecta ese tipo. Un caso limpio aprueba si el agente no reporta nada. src/evaluator.py::compute_metrics agrega esto en precisión, recall, F1, success rate, confiabilidad (corridas sin excepción) y latencia promedio.

6 hallazgos: 3 de estilo (RuboCop, severidad baja) y 1 de severidad alta — el endpoint de login renderiza la respuesta de éxito y la ejecución sigue hacia el render de "unauthorized", un double-render que rompe el endpoint para todos los requests. Además, severidad media por exponer el objeto User completo en render json: { user: user } y severidad media por no tener tests automatizados para el flujo de login. También reportó 3 hallazgos positivos: uso de has_secure_password, User.find_by(email: params[:email]) parametrizado en vez de interpolado, y la columna password_digest correcta en el modelo.
